## BandwagonHost Looking Glass 是什么？

Looking Glass 是运行在机房侧的网络测试工具。你可以在页面中输入自己的公网 IP，选择 Ping 或 Traceroute 等测试，让机房服务器向你的 IP 发起探测。结果可以帮助你查看往返时延和路由路径。

它和在本地电脑上直接 Ping 测试 IP 的方向不同：

- **本地 Ping 测试 IP**：观察从你这里到机房测试地址的连接。
- **Looking Glass 测试你的 IP**：观察从机房侧返回你这里的路径。
- **SpeedTest**：测试页面支持时，可观察下载或上传速度；它与路由追踪不是同一类测试。

互联网路由通常不保证两个方向完全一致。所以，单看本地 Ping 或单看 LG 都不够。要评估某个机房，最好两边都测，再结合你的实际用途判断。

## Ping、Traceroute 和 SpeedTest 分别看什么？

### Ping：看往返时延是否稳定

Ping 会显示探测包往返所需的时间。查看时不要只盯着最低的一个数字，还要看多次结果是否稳定、有没有明显的波动或丢包。

低延迟有助于交互频繁的服务，但 Ping 并不直接告诉你带宽够不够，也不能说明晚高峰一定流畅。一个节点在某个时刻延迟较低，不等于所有时段都能维持同样表现。

### Traceroute：看路径经过哪些网络

Traceroute 会逐跳显示探测包经过的路由节点。它适合用来检查路径是否经过预期的网络、是否出现明显绕行，以及响应从哪一段开始变慢。

但中间某一跳显示 `*` 或没有响应，不一定表示链路故障。部分路由器会限制或忽略这类探测包；应结合后续节点和最终目的地址是否可达来判断，别看到一个星号就给整条线路判死刑。

网上常见的线路识别方法会参考节点 IP 段或 AS 信息，但单凭一个地址前缀就断定整条路径属于某种线路并不稳妥。网络路径可能随运营商、路由策略和时间变化。把 Traceroute 当作路径线索更合适，不能代替实际业务测试。

### SpeedTest：看吞吐表现，不解释路由

若页面提供 SpeedTest，可以测下载、上传或抖动等指标。结果受客户端网络、浏览器、测试服务器负载及测试时间影响。它能补充吞吐信息，却不能单独解释为什么某段路由绕行，也不代表所有目标网站都能达到相同速度。

## 怎么解读测试结果，避免看错？

建议把结果分成三个问题来看：

- **延迟是否适合用途？** 远程终端、游戏或实时交互通常比静态文件服务更在意响应时间。
- **路径是否符合预期？** 如果目标用户主要在某个地区，观察路径是否经过合理的网络和出口。
- **表现是否能重复？** 在不同时间、不同设备或不同接入网络中复测，避免把偶然的好结果当成稳定表现。

如果 Traceroute 中间出现超时，但最后一跳仍有响应，不能仅凭中间超时就认定目标不可达。相反，如果最后目的地址也持续无法响应，还需要用本地测试、其他网络或不同测试方式交叉检查。

也要留意测试对象是否一致：机房网页测试到你的 IP，与本地 Ping 一个测试 IP 是两个方向；SpeedTest 又是另一种测量。将它们混成一个“速度分数”，结论容易失真。

## Looking Glass 不能替你回答什么？

LG 对机房选择有帮助，但它不是完整的购买验证工具。它无法保证：

- 你的应用在真实负载下会达到某个固定速度；
- 线路在未来每个时段都保持当前路径；
- 测试页面当前显示的节点就是所有套餐都能选择的机房；
- 测速结果等同于面向真实用户的网页加载体验。

如果你在运营网站或服务，最好在购买后用自己的应用、目标地区的网络和真实访问路径再做检查。测试节点只提供一个参照点，用户访问你的服务还会经过各自的运营商、DNS 和应用层。

## 常见问题

### Looking Glass 页面打不开怎么办？

先确认页面地址是否仍然可访问，再换一个已知测试入口尝试。不同机房页面相互独立，一个页面暂时打不开不代表整个网络都不可用。也可以稍后重试，或在页面正常打开后检查测试功能是否可用。

### Traceroute 出现 `*` 是线路有问题吗？

不一定。中间路由器可能不响应探测包。看后续节点是否继续返回结果，以及最终目标是否可达；如问题持续，再换测试时段或接入网络复测。

### 本地 Ping 很低，实际连接仍然卡，为什么？

Ping 主要反映探测包往返时间，不等于应用吞吐或晚高峰体验。可再检查 SpeedTest、Traceroute、丢包和应用服务器负载，并在实际使用时段复测。

### 能不能只靠 Looking Glass 选套餐？

不建议。LG 主要用于比较网络路径和基础时延；套餐还要核对内存、CPU、存储、流量、计费周期及可选地点。先缩小候选机房，再对照套餐资源，会比只看一个 Ping 数字更可靠。
